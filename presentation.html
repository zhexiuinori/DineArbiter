01 — PROBLEM DEFINITION
群体餐饮决策的三重困境

02 — METHODOLOGY
三阶段决策流程：采集 → 聚合 → 裁决
STAGE 01 会话初始化

创建决策会话，设定空间约束（区域）、时间约束（用餐时间）、规模约束（人数上限）、预算约束（人均区间）与硬性排除条件。

Avg. 60s / session
STAGE 02 偏好采集

基于卡片滑动交互的结构化偏好采集。每位成员对预定义标签执行三分类判断（心动/避雷/随意），并支持自由文本输入与图片辅助表达。

Avg. 30s / person
STAGE 03 智能裁决

LLM 接收全量偏好数据，执行多维度冲突消解与帕累托寻优，输出最优餐厅推荐、个性化理由生成与备选方案排序。

Automated
LLM 驱动的冲突消解 — DeepSeek V4 Pro 理解复合偏好约束，生成兼顾各方诉求的个性化推荐理由
卡片式偏好采集范式 — 借鉴 Tinder 交互模式，降低表态心理门槛，提升偏好采集完整度与参与率
个性化理由生成 — 为每位参与者生成"无法拒绝的理由"，将群体最优解转化为个体认同
三层容错降级机制 — LLM API → 云函数本地算法 → 前端本地算法，保障任意网络环境下的可用性
